# T14 verification

Implemented native clipboard history and SDR output/region screenshots on the
pinned Zig 0.16.0 / Ghostty GTK / Aqueous stack. Data-control, screencopy and shared
memory declarations are generated from vendored, hash-pinned XML. Production
uses no clipboard/screenshot helper programs and does not replace the portal.

The private T14 suite uses generated Zig data-control producers, actual
`wl-paste` interoperability, actual Aqueous screencopy, and independent `grim`
references. It verifies disappearing/stalled/replaced owners, invalid UTF-8,
unsupported/sensitive MIME, payload/count/aggregate byte caps, PNG truncation,
dimension bombs and metadata stripping, broken paste readers, stale entry IDs,
all eight output transforms, fractional-scale output-local crops, save conflicts,
screenshot copy, keyboard capture that hides the panel, authentication and
native-lock privacy, output-removal cancellation/recovery, repeated panel
lifetimes, Material light and native GTK themes.

Native/reference PNGs for the eight transforms and fractional crops are retained
beside those screenshots. The pixel differences and exact integration binary
hashes are in `latest/report.json`. [metadata.json](metadata.json) records final
source/build identities. Regression reports retain the binaries actually tested;
security regression ran before the final tab/thumbnail, feedback and identity
refinements, and the final T14 suite re-exercised its lock/authentication paths.
Surface/identity regression was repeated after the final identity gate.

All fixtures use private displays, buses and a test PAM stack. No host clipboard,
display configuration, PAM policy, portal ownership or power state was changed.
Private input PNGs are generated by the test and omitted from retained evidence;
interoperability output and screenshots remain. Test helpers are never installed.

See [CLIPBOARD_CAPTURE.md](../../docs/CLIPBOARD_CAPTURE.md) for limits and semantics.
Isolated-window capture is intentionally unavailable. Region input currently
uses an explicit rectangle, not a pointer-drag selector. SDR shared-memory capture
is validated here; physical HDR/color and screen-reader acceptance remain open.
Clipboard PNG decode/re-encode and local atomic save are bounded synchronous
operations; the documentation records their latency implications. Screenshot
conversion itself is a cancellable worker. Memory erasure claims cover only the
explicit service-owned buffers, not copies in GTK or external processes.
