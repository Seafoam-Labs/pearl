# Notification filters concept

Open [index.html](index.html) directly in a browser. This self-contained
HTML/CSS/JavaScript mockup proposes notification filtering inside Pearl Settings.
It follows the existing Pearl Settings mockups and requires no server, installed
packages or network resources.

The [implementation plan](../../NOTIFICATION_FILTERS_IMPLEMENTATION_PLAN.md)
defines proposed matching behavior, saved preferences, runtime integration,
protocol lifecycle and native acceptance criteria for
[issue #26](https://github.com/Seafoam-Labs/pearl/issues/26).

## Try the layout

- Use **Add filter** or **Edit** to configure application name, Desktop ID,
  title, body and urgency conditions. Choose All/Any and Block/History only.
- **Save rule** adds changes to the preview draft. **Apply & save** updates the
  in-memory baseline; **Discard** restores it. Reload resets all sample data.
- Pause all filters with the section switch, or toggle individual rules.
- Expand **Test filters** and try Firefox / Download complete, then Software.
  The sample tester shows the matching rule names and resulting delivery.
- Do Not Disturb and Clear history change sample live state immediately;
  they do not become part of the preference draft.
- Choose **Light preview**, resize the window, and use **Sections** on narrow
  screens. Escape closes the editor or compact navigation and restores focus.

Other sidebar destinations link to the plan. The window decorations are static.
All notification data is illustrative. No settings file, notification service,
browser storage or external application is accessed.

## Verification and limitations

Local Chromium/Playwright checks passed for draft editing, adding conditions,
Apply/Discard, reversible deletion, immediate DND, Block/History only sample
results, paused filters, zero-condition prevention, keyboard dismissal/focus,
compact navigation, empty state, and no horizontal document or editor overflow
at 390, 560 and 1440 pixels. No JavaScript runtime errors were observed.
See [verification.json](verification.json).

The prototype's sample matching uses browser NFC/lowercase handling; it does
not implement the proposed authoritative Unicode case folding, notification
sanitization/truncation, all backend schema validation, D-Bus lifecycle, shared
draft concurrency, lock state or persistence. The pictured history is sample
content and is not regenerated by Test filters. These checks verify the mockup
only; production changes and native verification remain future work.
