IMPLEMENTATION PLAN

Extend Pearl’s existing controls.

Hardware brightness lives in Pearl. Aqueous already provides the screen-power protocol used by wlopm; Pearl already binds it directly.

01 / MODEL

Give every display an identity

Replace the single selected backlight with display records: stable identity, output association, backend, supported range, confirmed value, requested value, availability, and operation generation. Resolve connector/EDID matches conservatively; do not silently control an ambiguous monitor.

02 / SERVICE

Add external monitor brightness

Keep sysfs discovery and logind SetBrightness for built-in backlights. Add a Zig integration with libddcutil for supported external monitors, including device access and packaging. Run I/O off the UI thread, coalesce writes, read back results, and reject stale replies after hotplug.

03 / INTERFACE

Connect the flyout and shared controls

Extend panels.zig with a display picker and per-display status. Prefer the flyout’s output when it has a known brightness device; otherwise show an explicit available selection. Share the model with settings, brightness keys, pearlctl, idle dimming, and the OSD. Preserve minimum-nonzero backlight behavior.

04 / POWER

Reuse the native Wayland connection

Extend idle.zig’s output records with names and per-output actions. Share ownership with lifecycle idle blanking instead of starting wlopm. Define restoration on input for screens Pearl turns off; do not wake screens turned off by another owner. The preview’s restore button simulates that input path.

05 / VALIDATION

Cover the transitions

Verify mixed backlight/DDC setups, rapid slider changes, permission failures, reconnects, duplicate display identities, stale replies, sleep/wake, and OSD targeting. Test monitor power on physical hardware and confirm windows remain in place. Include keyboard, narrow-width, and light/dark UI checks.

LATER / OPTIONAL

Software dimming needs its own design

Displays without hardware brightness stay unavailable in the first version. A later Aqueous dimming capability would need coordination with Night Light, color management, and HDR. Pixel dimming must be clearly distinguished from hardware brightness.
