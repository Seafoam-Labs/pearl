# Standalone Pearl Greeter package

Build and install on Arch with:

```sh
cd packaging/arch-greeter
makepkg -si
```

This builds `pearl-greeter-git` from upstream Git. The package is independent of
`pearl` and `pearl-git`; it does not install the desktop shell or replace Aqueous's
session entry. To test uncommitted source changes, build against that working
source tree instead of the upstream Git source.

Installation creates `/etc/pearl/greeter.json` with `allow_uwsm: true` and
`wayland:aqueous.desktop` as the preferred session. Other installed sessions
remain selectable, and discovery falls back to an available entry if the preferred
ID is absent. Pacman preserves changes to both this JSON file and
`/etc/pearl/greetd.toml` using its backup/`.pacnew` handling. Configuration is
installed by the package, not generated by the unprivileged greeter on startup.

The package provisions the `pearl-greeter` system account and its home, state and
cache directories. It depends on ordinary Aqueous (providing `/usr/bin/aqueous`),
UWSM, greetd, D-Bus, polkit and the GTK runtime. It uses greetd's distribution PAM policy;
no separate fingerprint or locker PAM configuration is installed.

The native appearance helper and its polkit policy enable **Sync to greeter** in
Pearl Settings' Appearance page and the settings flyout. Authentication authorizes
copying the selected background and GTK/Material theme to the system greeter config;
login/session settings are preserved. GTK themes must be installed system-wide.
The new appearance is used on the next greeter start. Install a Pearl desktop build
containing the sync button to use this action.

Before installation, an existing `/etc/greetd/config.toml` is copied to
`/etc/greetd/config.toml.bak`. An existing `.bak` is preserved on upgrades and
reinstalls. If there is no config, no backup is created. The backup remains after
package removal.

The install hook selects `pearl-greeter.service` as `display-manager.service` and
sets `graphical.target` for the next boot. The greeter uses VT7, with a matching
`getty@tty7.service` conflict; VT1 remains available for console login. This service runs
`greetd --config /etc/pearl/greetd.toml`, leaving `/etc/greetd/config.toml` intact.
The previous display-manager selection and default target are recorded under
`/var/lib/pearl-greeter-setup/previous.json`. No service is stopped, started or
restarted by the package. Reboot when ready to use the new greeter.

Upgrades provision any missing account directories but do not change service
selection or overwrite administrator configuration. A masked/custom display-manager
unit causes automatic setup to report a failure instead of replacing that unit;
after resolving it, rerun:

```sh
sudo /usr/lib/pearl/pearl-greeter-setup enable
```

Restore the previous boot setup with:

```sh
sudo /usr/lib/pearl/pearl-greeter-setup restore
```

Package removal invokes the same restore operation before removing files. If
another display manager has since been selected, or Pearl has been disabled, that
choice is preserved. The saved account, user selection state and caches are not
deleted. Restore/removal does not stop the current session; reboot to use the
restored setup. The restore command also supports `--root /path/to/mounted/system`
for offline recovery.

Package and offline activation/rollback tests do not establish real PAM login,
VT/seat handoff or hardware compatibility. See the installed `GREETER_COMPATIBILITY.md`
for the remaining acceptance work.
